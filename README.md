# YouTube Transcriber

Paste a YouTube URL → preview the synced transcript → download as
`.txt` (readable), `.srt` (VLC / Premiere) or `.vtt` (web `<video>`).

TXT uses one line per cue (`[HH:MM:SS] text`) — easy to read and
LLM-friendly — preceded by a 4-line `#` metadata header (generic title,
video URL, language, fetch time). SRT/VTT carry explicit `start --> end`
timestamps with millisecond precision, so they stay in sync in players and
editors. VTT cue payloads are `&`, `<`, `>`-escaped per the WebVTT spec
(they render literally rather than as markup).

## Run

```bash
npm install
npm start
# open http://localhost:3000 (if 3000 is taken: PORT=8765 npm start)
```

Docker:

```bash
docker build -t youtube-transcriber .
docker run -p 3000:3000 youtube-transcriber
```

## CLI

```bash
node bin/yt-transcript.js <youtube-url-or-id> [options]
# or after npm link: yt-transcript <url-or-id> [options]
```

Options: `-f, --format <txt|srt|vtt>` (default `txt`), `-l, --lang <code>`
(default: first available track), `-o, --output <file>` (default: stdout),
`--list-langs`, `-h, --help`. Option values accept space or `=` form
(`--format=srt`); use `--` to end option parsing. Exit codes: 0 ok,
1 fetch failure, 2 usage error. Shares parsing, fetching, caching and
formatting with the server. The Docker image serves the web app only;
run the CLI from a checkout.

Example:

```bash
node bin/yt-transcript.js dQw4w9WgXcQ -f srt -l en -o out.srt
```

## API

- `GET /api/tracks?input=<url-or-id>` → `{ videoId, tracks: [{ languageCode, name, isAutoGenerated }] }`
- `GET /api/transcript?input=<url-or-id>&lang=en` → `{ videoId, lang, count, fetchedAt, cues: [{ start, duration, text }] }` (`start`/`duration` in seconds; `lang` optional, defaults to the first available track)
- `GET /api/download?input=<url-or-id>&lang=en&format=txt|srt|vtt` → file download named `<videoId>_<lang>.<ext>` (`format` optional, defaults to `txt`)

Accepted inputs: `youtube.com/watch?v=…`, `youtu.be/…`,
`youtube.com/shorts/…`, `/embed/…`, `/live/…`, `/v/…`, `/e/…`,
`music.youtube.com`, privacy-enhanced `youtube-nocookie.com` embeds,
attribution links, or a bare 11-char ID. (`input=` and `videoId=` are accepted
as the query param; when both are given, `input` wins. `format` is
case-insensitive; `lang` codes are matched exactly. There is no CORS support —
call the API same-origin or server-side.)

## Notes

- Videos need captions enabled; otherwise the API returns a clear 404.
  Private/deleted videos also report as unavailable rather than "disabled".
- Transcript fetching uses YouTube's unofficial timed-text endpoints via
  `youtube-transcript` and can be rate-limited per IP (HTTP 429) — wait and retry.
- `/api/*` is rate-limited (120 req/min per IP; `/api/health` is exempt,
  trailing slash or not) and sends `Retry-After: 60` with 429s. Successful transcript fetches are cached server-side for
  10 minutes (keyed by video + language, so repeated downloads of the same
  video don't re-hit YouTube). Note: behind a reverse proxy all clients share
  one bucket unless you configure `trust proxy`.
- The server drains connections on SIGTERM/SIGINT (20s grace) — safe to
  restart under Docker/process managers.
- Filenames default to `<videoId>_<lang>.<ext>`.
